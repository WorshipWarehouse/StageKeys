# Personal ratings and effect preset recovery

Closes the scoped data-loss gap in #99; related release gates #20, #11 and #17 remain broader. Startup now uses throwing archive readers to distinguish an absent first-run file from invalid/unreadable metadata. Settings displays **Personal Metadata Recovery** with separate previous-ratings and previous-effect-presets actions. Errors no longer silently authorize replacing an archive with an empty dictionary/list.

Valid existing JSON identities and settings retain their format. Successful saves atomically retain a validated `.previous` copy. Saves after a failed load are rejected before changing disk or the in-memory ratings/preset list. Explicit recovery validates the backup, retains damaged bytes, and restores the metadata without applying a preset to active instruments or changing current patches. Restart reloads recovered data normally. No previous successful save means there may be no recovery copy; restore an independent backup then. Disk space and permission to retain the damaged primary are required.

Both metadata archives have a 4,000,000-byte bound, in addition to existing entry/value validation. Over-limit files remain on disk and need recovery or an independent backup. The shared recoverable-file reader refreshes cached URL attributes after atomic replacement and reads bounded chunks with a total cap; session files retain their existing 64 MB limit, catalogs 16 MB, and optional catalog tags 2 MB. Recovery backup reads enforce each archive's bound too. Regular-file checks reject live/dangling symbolic links. The compatibility `load` helpers still return an empty value for callers that deliberately request a nonthrowing read; app startup uses `read`, and save protection is enforced independently.

`MetadataRecoveryTests` generates valid old-format files and interrupted writes; checks startup flags, refused UI saves, backup/damaged-byte retention, explicit recovery and restart, unchanged current setlist/effects, oversized primary hashes, unsafe links and invalid/missing backups. Existing effect-preset quality/legacy tests use a separate valid archive after verifying corrupt-write refusal; their parameter assertions remain intact. No installed user metadata is used by regressions.
