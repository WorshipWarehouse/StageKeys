# Library curation and imported processing (0.25)

Recommended is a curated flag: marked sounds first, alphabetical within each group. It is independent of ratings and insertion date. A sound's context menu can mark or unmark it. Unknown recommendation status is treated as unmarked, never guessed.

Imported free-preset display names drop trailing vendor labels, numeric vendor suffixes and the redundant Layered Patch label. IDs, sample paths and original names are retained. Inferred classification now recognizes guitars and plucks. Missing browsing Note Range tags receive suggestions from category (bass: left; leads: right; pads: full/mid; sequences: mid/right; other: full). These suggestions do not modify MIDI key splits. Explicit tags and explicit clears survive reloads. Inferred metadata is identified in the browser.

An optional personal `source-sound-tags.json` beside the user's library can supply authored metadata for exact-name, processed Sunday App entries. `Tools/catalog-tags.py` extracts only sound tags from an existing personal catalog export. Facets the export declares are copied; original templates win over saved copies; repeated tag names are listed once; and metadata the export does not declare stays unknown — an absent or empty facet is omitted rather than written as an authored empty clear, and a missing Source/Model is labelled `Not Tagged` instead of asserting a model. Values the app would refuse (an unrecognized Note Range or Complexity name) are dropped from that row and reported, so one unsupported value cannot discard a whole sound's metadata. Entries with unusable names are skipped and counted, an unexpected export shape is refused with a clear message, and the output is deterministic. Raw instrument imports are not relabeled as processed patches. Source catalogs and assets are not included in this repository or application. Invalid optional metadata is ignored. The legacy generated Felt Room entry receives authored tags once, preserving explicit range clears and recommendation overrides; future edits remain intact.

Direct channel imports previously loaded only the ExternalSound reference, discarding the saved library layer. They now use addLibrarySound so racks, nested processing, macro bindings, MIDI program, levels and bypass states survive. Existing free imports with missing racks continue to recover from matching library entries when selected. Existing customized nonnil racks remain unchanged.

The module's Rack FX link opens the existing sound settings rack editor. The library footer reports the processor count recursively, including bypassed processors. Imported effects remain in their original graph, separate from the three performance effect slots; they are not applied twice. Import reports no longer incorrectly claim that all effects and macros are discarded.

Remaining differences: inferred free-preset taxonomy is not authored Sunday metadata; source-native raw instruments still require reconstruction of their channel processing to match factory variants; unsupported Live processors and current DSP approximations remain documented per sound. Exact audible parity is not established by these metadata and routing fixes.

## Library workflow update (30 October 2026)

The library now distinguishes the two module outcomes in its header, primary button and accessibility labels: an empty module says **Add Sound**, a loaded module says **Replace Sound**. Cancel ends any audition and range preview before closing; it does not commit or discard the saved patch, and tag edits made through the context menu are already persisted. The same cleanup runs if the sheet is dismissed another way. A selection is committed only after the preview is ended, so a replacement cannot restore stale Audio Unit state.

Active filters appear as removable chips, including when the result list is empty, with a separate **Clear Filters** action. Each facet column scrolls independently and shows a no-values message when the other filters exclude every value; fixed Note Range choices and the Not Tagged choice remain available.

Re-selecting the current order keeps its chosen direction, and **Random** keeps its seed until another order is selected. Ties remain deterministic by name and then identity.

Tag provenance is recorded per facet for edits made after this version. `authoredFacets` marks explicit Note Range/Complexity edits and metadata loaded from the authored source-tag file; inferred name tags remain **Suggested**, and an absent optional facet remains **Not Tagged**. Legacy libraries without provenance keep their previous Suggested/unknown interpretation rather than being retroactively labelled authored. The footer shows the groups for the selected sound.

This update does not establish visual layout at real window sizes, physical Mac/iPad interaction, vendor-library compatibility, or audible/DSP parity. Those checks still require the relevant Mac or device qualification.

## Library state and tag-provenance pass (3 November 2026)

Two gaps from the 2 November completion review were closed in the browser and the pure model; the rest of that review's list stays open.

**Error state.** An unreadable saved catalog used to reach the library modal only as the app-level alert plus the empty state that says StageKeys ships without sounds — the one message that must never describe a preserved-but-unreadable catalog, because it invites importing over it. The modal now resolves its no-rows presentation through `LibraryEmptyState`: `noSounds`, `noMatches` and `catalogUnreadable` are distinct, only a readable catalog offers the import shortcuts, and the error case offers **Recover Previous Sound Catalog** next to the results as well as a persistent warning bar under the header. Recovery still runs the existing `recoverPreviousLibrary`, which retains the damaged bytes and leaves samples and patches untouched. Loading needs no separate state here: the catalog is read synchronously during store start-up and import progress is reported by the import sheet, not by the browser.

**Unknown tags.** Every tag facet now resolves through one normalized value list. A blank or whitespace-only value, a repeated value and the literal `Not Tagged` collapse into the single unknown value `Not Tagged`, in the fixed Note Range order where applicable. Before this pass Category, Type, Timbre, Articulation and Source could return an empty string: the facet menu dropped that value, so the sound could not be reached through the facet at all, while the footer classified the facet as **Authored** (or **Suggested**) rather than unknown. Personal source metadata had the same hole: `authoredFacets(for:)` recorded a blank value as a declaration. Blank values are now undeclared everywhere, so `Not Tagged` is offered as a filter option and the provenance summary stays truthful.

Verification: both regression programs are extended — `LibraryBrowserTests` covers blank values, canonical ordering, the Not Tagged filter and the three empty/error states, and `LibraryNoteRangeTests` covers blank authored metadata surviving a reload as unknown. The renderers, filter chips, independent column scrolling and stable direction/order behaviour from the 30 October update are unchanged and still asserted.

**One recovery control and a reachable clear action.** The error state previously rendered the same recovery button twice — once in the warning bar and once in the empty state — and hid **Clear Filters** behind the import shortcuts, so a live search could strand an unreadable catalog with no way to clear it. The bar now appears only when the catalog still lists rows, the empty state owns the action when no rows remain, and the clear action appears whenever a search or filter is active regardless of catalog state. Neither change touches the store: recovery is still the existing `recoverPreviousLibrary` path.

## Missing content: detection and repair (3 November 2026)

The release checklist asked for a Locate workflow with exact identity checks and portable managed copies (`Docs/PUBLIC-RELEASE-CHECKLIST.md`). Until this pass a library sound whose managed file had been moved or lost still looked **Playable**, and the failure appeared only after Add/Replace.

**Detection.** `ExternalInstrumentRack.contentIssue(for:)` reuses the load-time checks (bare file name, readable managed file, and the preset's own sample references) without loading anything, and the store records one issue per sound id when the library modal opens or the library changes (open, import, recovery, repair), not per keystroke. Browsing never touches the disk per row. A sound with missing content reports **Unavailable**, is not playable, stays listed in its collection so it can be repaired, and states whether the file itself or one of its samples is missing. Audio Units keep their own availability reason; detection never substitutes plugin state for content.

**Repair.** **Locate Sound File…** copies the chosen file into the managed `Imported Sounds` folder. `LibraryAssetRepair.restore` refuses an unsafe name (path, traversal, dot file, over 200 characters), refuses a directory, symlink or oversized source, refuses to overwrite a managed file that already exists, stages the copy under a temporary name, verifies it before publishing, and removes the staging file on failure. The user's original file is copied, never moved or altered. `LibraryRepair.accepts` requires its SHA-256 to match the retained managed-asset digest; a name match or a pre-conversion instrument digest is insufficient, and entries lacking that identity must go through import. Repair never rewrites the catalog JSON, because the entry's file name and location are unchanged.

Verification: `Tests/LibraryRepairTests.swift` (new, default gate) covers the verified copy, the no-overwrite rule, unsafe names, failed verification leaving nothing behind, directory/missing sources, all identity cases, and the browser's unavailable/listed reporting. Run on Linux against the real `Sources/LibraryBrowserModel.swift` (stub app types, temporary harness outside the checkout): 36 assertions pass. Still unverified here: the Xcode build, the SwiftUI present/hide behaviour of the Locate button, and an actual moved-library walkthrough on macOS or iPad.

Executed for this pass on Linux with Swift 6.1.2 against the unmodified `Sources/LibraryBrowserModel.swift` (stub app types, temporary harness outside the checkout): the existing model assertions of `LibraryBrowserTests` and `LibraryNoteRangeTests` plus the new ones, and a verbatim probe of the changed `SoundLibrary` authorship helpers. All passed. This is a model-level check only: it is not the repository test gate, not an Xcode build, and not UI interaction. `Tests/test-library.sh`, the universal Mac/iPad builds and every on-device qualification below remain unexecuted here.

### Audit correction: identity and repair scope

Repair now requires an exact retained SHA-256 of the managed asset (captured for new individual imports), and verifies the staged copy again before publication. A matching filename is never identity proof; a pre-conversion EXS/source digest does not identify a generated managed preset. Legacy/conversion entries without a managed digest must be reimported rather than guessed. Repair copies up to 2 GB without rewriting the located original. Missing dependent samples require storage reconnection or reimport; Locate repairs a missing managed file only. A refreshed issue-free row clears its previous unavailable status.

Mac audit verification: the actual `LibraryRepairTests`, `LibraryBrowserTests`, `LibraryNoteRangeTests`, `StoreTests` and `CatalogRecoveryTests` programs passed on the corrected tree. The repair regression now includes a full Store import/move/relink path, exact byte hashes, rejection of different bytes under the same filename, persisted digest round-trip and unchanged session bytes. Earlier Linux/stub outcomes above describe the original author environment; they did not establish these macOS guarantees.
