# Personal Mac-to-iPad sound packs

Refs #87, #8 and the native conversion milestones. This is personal device transfer, not a vendor-library distribution feature. Packs stay outside application/source distributions.

On Mac, open Import Sounds → Transfer Native Sounds to Your Other Devices, select native sampler entries and save a `.stagekeyspack`. Unsupported host presets, external MIDI destinations and Audio Units show their reason instead of being exported as silently silent sounds. Current per-sound effects, channel settings, macros/MIDI, tags and native sampler maps travel. Plug-in snapshots, original source archives, previous rack history, setlists, ratings and session settings do not. Original samples are copied unchanged and verified by SHA-256; preset sample references use portable relative tokens.

The writer first produces the existing version-1 folder-pack format and validates it with `LibraryBackup.read`. A single-file **STAGEKEYSPACK / version 1** container transports those files. It is a streaming, uncompressed StageKeys document, not ZIP; no new archive dependency is required. Each record carries a bounded UTF-8 relative name, 64-bit byte count, SHA-256 and payload. The full payload cap is 2,000,000,000 bytes, maximum 20,000 files and 4,096 UTF-8 bytes per path. Catalog/preset and manifest limits remain 16 MB and 2 MB. Larger libraries must be split into smaller personal packs.

Copy the document through Files/AirDrop and open it with StageKeys, or choose it in Import Sounds. Both app targets register the custom UTType/document extension and opening in place. Extraction verifies every record in a fresh temporary directory, rejects absolute/traversing/case-colliding paths, duplicates, trailing/truncated/altered data, oversized payloads and unlisted files, then checks the existing manifest/catalog. No archive link or executable-entry type exists. Incoming ineligible host/AU entries are reported and refused before catalog commit. Existing native IDs are skipped; the active setlist is never replaced. Cancel/failure retains the catalog and removes owned prepared assets/extraction data. Verification/extraction runs off the UI executor; cancellation is checked before installation/commit.

`PersonalSoundPackTests` builds an original generated EXS, exports, moves/unpacks/installs it into fresh app data, compares sample hashes/current settings and rendered Mac energy with effects, restarts, retries duplicates, cancels, and rejects malformed/unsafe/ineligible packs. `check-pack-document-type.py` validates actual build metadata on both targets; processing tests reject missing document declarations. These are software/clean-data checks, not physical iPad qualification.

Physical iPad AirDrop/Files receiving, memory/startup for a large piano and sustained-note comparisons across velocities remain required before #87 closes. The current device inventory showed a paired iPhone with no available tunnel, and no iPad; no physical-device result is claimed. Exact MainStage DSP equivalence also remains #10.
