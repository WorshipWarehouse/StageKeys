# Safe setlist file activation

The JSON file importer calls `PerformanceStore.load`. It now rejects Patch Lock before opening the source, preserving the current identity, snapshot, held notes, sustain and saved session/settings bytes. After successful decode/upgrade and preservation of the prior setlist, it follows local setlist opening by applying the patch, recalling its Tonic Pad state and updating the audio clock with performed tempo before saving. Locked patches recall their own tempo; unlocked ones use the existing global live tempo. The import source is not rewritten. No schema or content packaging changes were made.

## Reproduction and validation — 2026-11-04

Baseline: `eabe0c5a585493cf52bc19816bb1231ba4749296`. Generated SetlistActivationTests compiled against the unchanged prior core fail independently at “File import must respect Patch Lock” and, with the locked attempt omitted, “File import must recall the patch Tonic Pad state.” A third baseline run omitted only the already-proven pad assertions and failed at “Imported tempo must reach the rendered click clock.” The initial baseline compile used a different worktree header and failed a typedef redefinition; using the module’s original header resolved that setup error before the runtime reproductions.

The final regression uses generated WAV/sampler content, isolated data and the production offline graph at 48 kHz. It asserts no locked-import state/byte changes; valid import preserves the prior library entry, resets held notes/sustain/snapshot and recalls enabled/disabled pad state; source bytes stay unchanged. Rendered click intervals match 150 BPM for a locked import and retained 90 BPM for an unlocked import (eight-frame tolerance after initial transients). Restart retains the authored tempo-lock/pad settings. Malformed JSON leaves the active patch, held note and session bytes intact.

Five initial focused programs pass: SetlistActivationTests, StoreTests, TonicPadTests, SessionRecoveryTests and SetlistTemplateTests. The expanded final activation test separately passes against the same fixed production core. The full native suite reports 112 passes, 11 explicit skips and no failures. Final unsigned universal Mac and generic Simulator artifact gates, seven runner self-tests, inventory/content and accessibility checks pass. The expanded final test ran separately after the full run started; production code was unchanged. Results and 222 final input hashes are recorded in the accompanying verification JSON. Private-fixture skips are not exercised compatibility checks; PianoHeldNoteTests also reports pass without its optional private fixture.

## Limits and outstanding acceptance

Related #114, #111, #16 and #20 remain open. This is not portable packaging/deep-link support, full resource-transaction admission, AU failure isolation or complete sample-accurate tempo propagation across every effect/arp/sequencer. Existing successful-import Panic policy disables the click before recall; this change does not alter that policy. No native GUI, physical keyboard, physical iPad, audible stage, latency or soak qualification is claimed. StageKeys remains independently implemented; reference parity is not established.
